# Image-to-animation pipeline review — 2026-10-18

Reviewed against `docs/superpowers/specs/2026-10-18-modular-2d-3d-blender-filmcraft-pipeline-design.md`, which is marked Draft for Review. This is a code review, not a fresh Blender/FilmCraft end-to-end certification. The cutter was implemented separately; the findings below in the existing Track B pipeline remain open.

## Findings, in priority order

1. **P1 — The file server exposes arbitrary readable local files.** `server.ts:157–174` accepts an unrestricted absolute `path` on `/vault-image`; `server.ts:260–273` serves any existing workspace file without an allowlist, including dotfiles. Wildcard CORS makes these reads available to other browser origins. The server has no explicit loopback hostname. Restrict to realpath-contained media/export roots, reject dotfiles/symlink escapes, bind loopback and restrict origins before treating it as a trusted agent bridge. No secrets were fetched during this review.

2. **P1 — Archetype routing does not control the Blender builder.** `pipeline/blender53_bridge.py:47–80` accepts an archetype, but the generated scene always creates the same silhouette mesh and biped rig, including ears, paired arms/legs and backpack (`:381–446`). `ARCHETYPE` is metadata rather than a geometry/rig dispatch. `glb_path` and `strip_costume` are unused. The bridge clears the existing scene (`:89–101`). This violates G2/G3 and the explicit anti-goal against silently treating fish, sun and boat as bipeds. Dispatch real builders, validate archetype/verb compatibility and scene ownership before execution.

3. **P1 — QA can certify failure without evidence.** `pipeline/jev_qa_verifier.py:197–204` returns constant acceptance and high confidence when there is no API key. `:268–271` accepts at 0.85, while the installed image-to-animation skill specifies 0.88; `:287–292` marks the report passed from scores even if the adjustment says to reject. Blender consumes the returned slices without gating on `passed` (`pipeline/blender53_bridge.py:61`). Metrics inspect the hero rather than all views and do not compare an independent reference silhouette, so they cannot establish that ears/feet were not lost. Record unavailable QA honestly, enforce deterministic metrics on every view and require the acceptance choice as well as thresholds. Keep model judgment separate from measured facts.

4. **P1 — Asset and output choices are dropped.** `studio_pipeline_cli.py:29–44` consumes Q1 and verb but ignores Q2 part choices and Q3 target. `:91–161` always invokes Blender then FilmCraft regardless of target; `--frames` is parsed but not passed on. Blender hardcodes 48 frames (`pipeline/blender53_bridge.py:517–527`, `:671`). `/api/run-pipeline` passes a slug and intake strings but no uploaded image (`server.ts:216–242`). Unknown image resolution silently returns Hopper (`pipeline/vault_characters.py:141`). Together these paths can animate the wrong character, produce the wrong rig and report the wrong export mode. Resolve source identity explicitly and pass a typed plan through every stage.

5. **P1 — Existing sheet slicing loses poses and exports contaminated anatomy.** `pipeline/vault_characters.py:419–448` takes only y=8%..49% of action sheets and then treats those frames as turnaround views. The second row is dropped. `:498–527` extracts rectangular body regions with no part segmentation, parent graph, pivots, source transforms or occlusion handling. Aspect ratio is not a reliable sheet classifier. The new cutter addresses sprite extraction independently; the old Blender/QA callers have not been switched to it because its schema and review policy differ.

6. **P2 — The modular intake caller and topology function disagree.** `src/index.ts:36–47` passes a decision object to `doesRegionNeedBendLoop`, whose signature is `(jointType, maxBendDeg)` (`src/topology/decideTopology.ts:1–18`), then reads nonexistent return properties. Reproduction with `bun -e` calling `evaluateThreeQuestionIntake` returns `"topologyDecisions":{"head":{},"arms":{}}`. Its unknown-Q1 fallback also assigns the entire classifier result object to `archetype` (`src/index.ts:28–31`). Bun bundling does not establish TypeScript type correctness. Add entrypoint/API integration tests and an actual type check.

7. **P2 — Geometry functions do not yet implement the design's mesh guarantees.** `src/topology/decideTopology.ts:20–90` appends independent rings without stitching them into the input mesh; ringCount=1 generates degenerate triangles. `src/topology/skinning.ts` changes visibility data only, without binding or swapping geometry. `pipeline/topology_parity.py` reads GLB accessor counts and computes loops=3×tris; it never compares Blender vertices/edges/bones, and the bridge never calls it. G4's 100% parity claim is therefore unverified. The current tests prove arithmetic properties and string presence, not watertight joints or parity.

8. **P2 — Render/import success is weaker than advertised.** Blender has no headless fallback and requires its live TCP service. Its camera is perspective (`pipeline/blender53_bridge.py:618–630`), with no transparent orthographic output setup. FFmpeg uses an interpolated shell command and ignores status (`:714–719`), permitting shell interpretation of a crafted path and stale MP4 reuse after a render failure. Artifacts share `slices/` and `character_turnaround_rig.blend` in the output directory, so runs can overwrite each other. `pipeline/filmcraft_bridge.py` ignores sequence/render exit failures and can fall back to a source frame; it marks success from file existence, not verified timeline placement, and never uses `final_mp4_out`. Use argument-array subprocesses, isolated run folders, fresh-artifact checks and verified timeline/export results.

9. **P2 — Modularization and secondary targets are partial.** The compatibility HTML is still over 7,000 lines with its own animation/export/intake logic. `src/archetypes/index.ts` centralizes templates, with 20 biped bones, 7 fish, 3 sun and 3 vehicle bones; these differ from the spec's documented counts and Blender's skeleton. `src/exporters/blender53ScriptExporter.ts` builds an armature only; its verb/render path do not cause animation/rendering. `src/exporters/videoCodeExporter.ts` emits a generic moving image or colored EffectCraft solid, not layered character animation. The requested modular GLB exporter and part-slicing module are absent. The Ask Omarchy endpoint returns a plan/command rather than spawning an actual agent. The skill references nonexistent `slice_character_sheet`, a nonexistent `jevEvaluation` report field and output paths/status keys that differ from the implementation.

## Cutter deliverable and limits

`pipeline/pose_and_part_cutter.py` adds an offline path with no model calls. It exports full action sheets, five-view references, common-scale transparent PNGs, an atlas with pixel rectangles and Three.js UVs, source coordinates, anchors, per-part polygons/pivots/parents, an editable layout and p5.js/Three.js rendering helpers. The unified CLI now exposes `cut-sheet`.

The source directory contains **26 action sheets and 32 turnaround sheets**, not a single uniform 10-frame layout. Captions include repeated and mislabeled actions, 10/11/12 action frames, and Maisy's additional hero reference. Profiles copy the actual source captions; they do not relabel a sitting or duplicated running image as a missing action. Source SHA-256 checks prevent applying a profile to different artwork with the same filename. The resulting 458 frames are static references, not 458 temporal animation frames.

Every automatic part cut remains `needs_review`. Flat painted sheets cannot reveal a complete arm hidden behind a torso, reconstruct the costume beneath a backpack, or prove joint caps exist. Automatic cuts are visible-pixel region estimates, not semantic anatomy segmentation. Decorated panels, ground patches, cream-fur/background ambiguity, overlapping tails and source-cropped legs can need explicit masks. Warnings and per-frame crop-boundary checks expose these cases. The exploded template supplies the exact generation prompt for complete hidden artwork; the cutter can ingest that separate 3×3 parts sheet and export a puppet binding for manual joint-position review.

## Verification scope

Python regression tests cover both action rows, five views, pale enclosed interiors, grid backgrounds, explicit masks and pivots, caption exclusion, invalid input, optional absent exploded parts, puppet bindings and unified CLI invocation. The original Python and Bun suites are also run. The entire vault batch is exported and contact sheets inspected. No Blender scene or FilmCraft project was changed during this task; their architectural gaps above are code-review findings, not claims of a newly validated end-to-end pipeline.

Final cutter evidence: 58 sheets, 458 frames and 3,175 visible-pixel part cutouts exported with zero batch errors. 55 frame crops touch foreground at a crop boundary and are flagged in their manifests. 14 Python tests and 5 Bun tests pass; the runtime module bundles successfully. Independent review identified two existing-alpha handling defects, both fixed with regression coverage. `exports/pose_and_parts/index.html` is the visual export index; `validation_summary.json` records counts and limitations.
