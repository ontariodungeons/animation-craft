Magic Studio Panel Contract

Every panel in the Studio carries the same small record. The TUI and the CLI read that record for every panel, so a new panel needs no new command, no new feedback field and no new Rust code, and anything on screen without a record is reported as unconfigured.

The config

One record per panel

A panel is a header, a body and a status, with one light. Its state is four values. This is the whole thing the TUI and CLI ever need to know about a piece of UI.

{ "id": "block-song", "label": "Song",
  "signal": 1,          // 0 idle · 1 in use · 2 needs you · 3 problem
  "open":   true,       // visible / expanded
  "busy":   false,      // work in flight (drawn as a pulse)
  "dirty":  false,     // unsaved edits
  "look":   "control" } // style, chosen from a fixed list (Task 8)
SignalLightMeaningComes from state
0greyidle, or off. A Studio that is off is grey, never red.idle
1greenin use. With busy it pulses ready, working
2yellowneeds youneeds-attention
3redproblemfailed

The state-to-signal table exists once, in companion-boxes.js. CSS draws the light from data-signal; the TUI colours it from the Rust Signal; nobody else maps states.

Types

What every panel is made of

Rust has no class inheritance, and the shell is plain JS, so "every panel inherits the contract" is done by composition: each panel has one record and is drawn by one component. The record is the only thing readers depend on.

Two files hold all of it. Every element has an entry in components.json and inherits its look from its component in style.css. No inline styling: data geometry (a placement's x/y/w/h, a clip's start) is passed as CSS custom properties that the component rule reads. Refactor as you go: every commit that touches a UI file must lower one of that file's lint counts.

Companion plan · done in part

Video project: four answers became one

What was wrong

  • workshop.status returned the stored path and a guessed one side by side; the guess could be any .fcproj in the folder.
  • workshop.set_target built the new target's project and threw the path away, so the old target's project stayed the answer.
  • The project catalog judged "editor ready" from the guess.

What it is now (872a041)

  • Status returns video_project_path and video_project_exists, nothing guessed.
  • set_target stores the project it builds.
  • Three regression tests in crates/engine/tests/wiring_state.rs, run by the commit hook.
  • Next: the UI reads that one field, then the video panel turns red when a target is set but its project is missing.
Rules every task keeps
  • Facts only from events. Empty is not an error; a closed Studio is reported as unavailable, never as zero panels.
  • Nothing per panel in Rust or tests: readers loop over items.
  • Colours only as :root tokens. No silent fallbacks, such as a default green dot when the registry is missing.
  • Pets never move on their own clock: finite bursts, one timer each, a cooldown between bursts.
  • The TUI reports UI health: every flagged element carries a reason, untracked (no config entry) or unstyled (inline visual style), so random UI shows up as a count. Bad looks in components.json fail at commit time.
